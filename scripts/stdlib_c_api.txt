# 136.73 -- the tk_* symbols that no .tki export reaches, nothing in src/
# calls and no toke spelling names, each decided.  Read by
# scripts/check_tki_coverage.py (`make render-stdlib-internal`,
# `make check-tki`), which classes them on docs/reference/stdlib-internal.md.
#
#   <tk_symbol> c-api <cite>[,<cite>...]   # reason
#   <tk_symbol> dead  [<cite>...]          # reason
#
#   c-api  a documented C entry point, kept for C callers (an embedder, a C
#          unit test under test/stdlib/, a conformance harness).  At least one
#          cite is required; every cite is a repo file that names the symbol
#          -- the header that declares and documents it, a doc page, a test.
#   dead   nothing reaches it and nothing documents it as API.  The reason
#          names what decides it (a story, a defect); deleting it is a glue
#          decision this file does not make.
#
# `make check-tki` FAILS on: a `dead` symbol with no line here (UNTRIAGED);
# a line whose symbol is gone or is now reached some other way (STALE --
# delete the line); a cite that does not exist or does not name the symbol
# (BADCITE).  Same shape as scripts/core_reach_triage.txt (136.50a).
#
# Not here: tk_cap_require_path / _net / _cmd / _env.  The scoped gate macros
# in capabilities.h (TK_REQUIRE_PATH / _NET / _CMD / _ENV, 138.19) call them in
# every fs/net/env/process sink; 136.73 taught the classifier to follow a
# header macro into the .c files that expand it, so they are `c-internal`.
