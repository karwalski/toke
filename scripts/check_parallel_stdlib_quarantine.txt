# check_parallel_stdlib_quarantine.txt — ungated parallel module descriptions
# (read by scripts/check_parallel_stdlib.py; story 135.11)
#
# One repo-relative path per line. Every entry is a file that SHOULD NOT EXIST:
# a second description of a stdlib module that no gate reads. The list exists
# only so the gate can be switched on before the whole population is cleared.
#
# THIS LIST ONLY EVER SHRINKS. Adding a line is not a way to land a new
# parallel file — the gate rejects new ones by design. An entry whose file has
# been deleted is STALE and fails `make check-parallel-stdlib`, so removing the
# file forces removing the line.
#
# Why each class is here (135.11, 2026-09-22):
#
#   stdlib/<m>.tk   A toke reimplementation of a module whose real
#                   implementation is C in src/stdlib/. Nothing resolves these:
#                   src/llvm.c resolves imports to .tki + C sources, and
#                   TKC_STDLIB_DIR is src/stdlib. Measured 2026-09-22 with
#                   `toke --check` (3.0.0): 18 of 21 did not even parse --
#                   17 failing at lex/parse in a dialect the compiler no longer
#                   accepts, 1 (path.tk) at type_check. sha256.tk and
#                   strpure.tk have no .tki, no C core and no importer at all.
#                   See also story 127.126, which found the same for toon.tk
#                   and noted that no make target compiles the stdlib's own
#                   toke sources -- which is why nobody noticed.
#
#   stdlib/<m>.md   The pre-move documentation location. These were validated
#                   once by the 48.4 story series (2026-04-07) and then
#                   superseded by docs/stdlib/<m>.md, which `make check-docs`
#                   gates. Only files that HAVE a docs/stdlib counterpart are
#                   listed; the ones that do not are live documentation in the
#                   wrong place and must be MIGRATED, not deleted (see the
#                   note at the end of this file).

# --- NOT quarantined: live docs in the wrong place (11) ---
# These stdlib/*.md had NO docs/stdlib counterpart, so they were the only copy
# of that documentation and deleting them would have lost it. They were still
# ungated. They needed MIGRATING into docs/stdlib/ (where check-docs then
# validates their examples), not removing. The gate deliberately ignores this
# class so it cannot be satisfied by deleting real content.
#
# CLEARED by story 135.13 (2026-09-23). All eight module docs were git mv'd
# into docs/stdlib/ and rewritten against the built compiler:
#
#   stdlib/infer.md      -> docs/stdlib/infer.md
#   stdlib/keychain.md   -> docs/stdlib/keychain.md
#   stdlib/mdns.md       -> docs/stdlib/mdns.md
#   stdlib/mlx.md        -> docs/stdlib/mlx.md
#   stdlib/securemem.md  -> docs/stdlib/securemem.md
#   stdlib/tls.md        -> docs/stdlib/tls.md
#   stdlib/vecstore.md   -> docs/stdlib/vecstore.md
#   stdlib/webview.md    -> docs/stdlib/webview.md
#
# THE NINTH WAS NOT WHAT IT LOOKED LIKE, AND THAT IS A HOLE IN RULE 2.
# stdlib/llm_tool.md was counted in this class because Rule 2 matches
# counterparts by EXACT BASENAME, and docs/stdlib/llm_tool.md does not exist.
# Its counterpart is docs/stdlib/llmtool.md -- the same module under the
# no-underscore spelling 113.2a mandated. The docs/ copy is a strict superset
# (5 functions to 3, all four types, the correct `llmtool.*` call-names),
# while stdlib/llm_tool.md documented `llm.withtools`, `llm.chatwithtools`
# and `llm.submitresult` in the `std.llm.tool` dotted sub-namespace that
# 136.17 found resolved to nothing. So it was a DUPLICATE, not a unique copy,
# and 135.13 deleted it rather than migrating it.
#
# Rule 2 will miss the next one the same way. A module renamed to drop an
# underscore leaves its old doc invisible to the exact-basename check. The
# fix is to compare against the docs/stdlib basename with `_` stripped as
# well as verbatim; it is not made here because this file is data, not code.
#
#   stdlib/CONTRIBUTING.md
#   stdlib/README.md
#
# (stdlib/README.md and stdlib/CONTRIBUTING.md are ordinary directory READMEs,
#  not module docs, and are not in this class. They are all that remains.)
