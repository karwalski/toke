**Status:** Complete (Story 2.12.1)

This file is the normative error code registry for the toke legacy profile.
Error codes are stable -- never renumber or change the meaning of an existing code.

See `spec/toke-spec-v0.3.md` Appendix A for the diagnostic JSON schema.

---

## Series

| Series | Range | Stage |
|--------|-------|-------|
| E1xxx | 1000--1999 | Lexer |
| E2xxx | 2000--2999 | Parser |
| E3xxx | 3000--3999 | Name resolver |
| E4xxx | 4000--4999 | Type checker |
| E5xxx | 5000--5999 | Arena validator |
| E6xxx | 6000--6999 | IR lowerer |
| E8xxx | 8000--8999 | FFI |
| E9xxx | 9000--9999 | Codegen / internal |
| Wnxxx | same ranges | Warnings. The number, not the emitting pass, sets the JSON `stage` (W1001 is `lex`, W5001 `arena_check`, W8001 `ffi`) |

The JSON `stage` field of every diagnostic is derived from its number by
`phase_for_code` in `src/diag.c`: `lex`, `parse`, `name_resolution`,
`type_check`, `arena_check`, `ir_lower`, `ffi`, `codegen`. Where a code is
emitted by a different pass than its series names, the section's Stage row
says so in parentheses; `scripts/check_error_codes.py` gates the first word.

## Lexer Errors (1xxx)

### E1001 -- Invalid escape sequence

| Field | Value |
|-------|-------|
| **Code** | E1001 |
| **Stage** | lex |
| **Severity** | error |
| **Message** | `invalid escape sequence in string literal` |
| **Fix field** | absent |
| **Conformance test** | D001, D006, D007, D008, D010, D011, D012 |

**Notes:** Emitted when a backslash in a string literal is followed by a character
that is not one of `"`, `\`, `n`, `t`, `r`, `0`, `x`, or `(`. Also emitted when
`\x` is not followed by exactly two hex digits.

**Example trigger:**
```text
m=test;
f=bad():$str{<"\q"};
```

### E1007 -- Unterminated comment

| Field | Value |
|-------|-------|
| **Code** | E1007 |
| **Stage** | lex |
| **Severity** | error |
| **Message** | `unterminated comment: the '(*' at L:C is never closed, so the rest of the file is comment` |
| **Fix field** | absent (where the missing `*)` belongs, or whether the inner `(*` should go, is not decidable) |
| **Conformance test** | D101, C325 |

**Notes:** Comments nest (toke-spec-v0.3.md §8.10), so a `(*` inside a comment
opens another level. `(* reads COUNT(*) from t *)` therefore leaves the outer
comment open: its `*)` closes the nested level. Before story 138.10 the lexer
stopped silently at end of file, so every declaration after such a comment
vanished and `--emit-llvm` succeeded without them. The diagnostic sits on the
outermost `(*` and its message names the nested `(*` that took the `*)` (or,
when several levels are open, the innermost one).

**Example trigger:**
```text
m=test;
(* reads COUNT(*) from the table *)
f=main():i64{<1};
```

## Warnings (W1xxx)

### W1001 -- Lossy cast

| Field | Value |
|-------|-------|
| **Code** | W1001 |
| **Stage** | type_check (the number is in the lexer range for historical reasons; 127.223) |
| **Severity** | warning |
| **Message** | `potentially truncating cast from '<T1>' to '<T2>'` |
| **Fix field** | absent |
| **Conformance test** | -- |

**Notes:** An explicit `as` cast narrows the value (e.g. `i64` to `i32`). The
compiler warns that the cast may silently truncate data at runtime. This is a
warning, not an error -- the code is valid but potentially lossy.

---

### W1010 -- String interpolation `\(…)` not supported in the legacy profile

| Field | Value |
|-------|-------|
| **Code** | W1010 |
| **Stage** | lex |
| **Severity** | warning |
| **Message** | `string interpolation \( is not supported in the legacy profile; use str.concat() instead` |
| **Fix field** | absent (127.243: the compiler emitted "use str.concat() for string composition", which is advice -- the rewrite needs a std.str import, an alias and a conversion for each non-str piece; D005 pins the absence) |
| **Conformance test** | D005, D009 |

**Notes:** The `\(` sequence inside a string literal triggers this warning. The
lexer consumes the parenthesised content as part of the string literal. There
is no mechanical rewrite, so the diagnostic carries no `fix`; the message names
`str.concat()`.

**Example trigger:**
```text
m=test;
f=interp():$str{<"hello \(name)"};
```

## Parser Errors (2xxx)

### E2001 -- Declaration ordering violation

| Field | Value |
|-------|-------|
| **Code** | E2001 |
| **Stage** | parse |
| **Severity** | error |
| **Message** | `declaration ordering violation` or `module declaration must appear first` |
| **Fix field** | absent (127.240: the compiler emitted "reorder declarations: m= first, then i=, t=, f=", which named no declaration or target and omitted constants and `let` globals; D112 pins the absence) |
| **Conformance test** | G024, D112 |

**Notes:** A toke source file must follow the declaration order:
`m` (module) then `i` (import) then `t` (type) then constants then `f` (function).
This error fires when a declaration appears out of order or when `m=` is missing.

**Example trigger:**
```text
f=bad():i64{<0};
```

---

### E2002 -- Unexpected token

| Field | Value |
|-------|-------|
| **Code** | E2002 |
| **Stage** | parse |
| **Severity** | error |
| **Message** | `unexpected token` |
| **Fix field** | absent |
| **Conformance test** | C326, C327, C335, D107, D108 |

**Notes:** The parser encountered a token it cannot consume in the current
grammatical context. This is the general-purpose parse error for tokens that do
not match any expected production.

Two specific messages (story 138.10), both without a fix field:

- `x.a=9;` -- a bare `=` after a field access at the head of a statement --
  says a struct field cannot be assigned (the grammar's AssignStmt takes a
  plain name) and shows rebuilding the value on a `mut.` binding. The
  "use `==` for equality" advice is kept for conditions such as `if(n=1)`;
  it was wrong for a field store, where following it produced a discarded
  comparison. Conformance: C326.
- a keyword or reserved literal used as an import alias (`i=sc:std.str;`)
  says so, once; later `sc.name` uses parse as that alias rather than
  cascading. Conformance: C327.

**Example trigger:**
```text
m=test;
f=bad():i64{<1 @};
```

### E2003 -- Missing semicolon

| Field | Value |
|-------|-------|
| **Code** | E2003 |
| **Stage** | parse |
| **Severity** | error |
| **Message** | `missing semicolon` |
| **Fix field** | absent (127.240: the compiler emitted "insert ';' after expression", which is advice -- `let x=1 y` with ';' inserted is E3011; D111, D113 pin the absence; `got` and `expected` carry the facts) |

**Example trigger:**


### E4031 -- Type mismatch

| Field | Value |
|-------|-------|
| **Code** | E4031 |
| **Stage** | type_check |
| **Severity** | error |
| **Message** | `type mismatch: expected '<T1>', got '<T2>'` |
| **Fix field** | present (contextual, e.g. `"cast RHS to i64 using 'as'"`; for `x==@()` / `x!=@()`, the rewritten comparison `"x.len==0"` / `"x.len!=0"`) |
| **Conformance test** | D086, D570-D574, C038, C249, C1810 |

**Notes:** The workhorse type error. Emitted for mismatched operands in binary
expressions, mismatched function arguments, mismatched binding annotations,
mismatched assignment sides, and mismatched return values. The fix field, when
present, suggests an explicit `as` cast. For a function argument it is present
only when both types are numeric and the cast is not float to integer (story
127.220): `as` does not convert an array, map or struct to `str`. For a
scalar (integer, float or bool) passed where a stdlib parameter is `str`, the
fix is `"wrap the argument in a string interpolation"` -- `x` becomes
`"\(x)"`, which is a `str` for every scalar type (story 127.14; kept by
127.243 as deterministic); a composite argument gets no fix, since
interpolating it is E4032.
For a binding annotation, an assignment, a binary operand and a return value it is
present only when the cast cannot change the value -- any integer into `i64`,
or `f32` into `f64` (story 127.230); a narrowing, a non-numeric pair and an
array of another element type get no fix. An integer literal that fits the
declared integer type is not a mismatch at all (`let b:u8=5`).

**`==` / `!=` the emitter has no equality for** are E4031 too. Both operands
struct or sum values (story 138.9, loke T-14):
`'==' does not compare struct or sum values ('<T>') ...`, with no fix (an opaque
`.tki` handle and `$none` keep their handle comparison). An array operand,
whatever the other operand is (story 138.20, loke T-60; owner decision
2026-11-15, register 1.2 (a)):
`'==' does not compare arrays ('<L>' == '<R>'): toke has no array equality; test
emptiness with .len or compare the elements`, `expected` `a scalar or str
operand`. `got` is the array the comparison is about: when exactly one operand
is the literal `@()` and the other is an array, the other operand (`@()==x` with
`x:@i64` gives `@(i64)`, not the literal's `@(?)`); otherwise the left operand
if it is an array, else the right. An array compares with nothing, so the
refusal does not wait on the other operand: one whose type an earlier error left
`unknown` still draws it, with no fix. Through 3.2.0 this compiled: against
the literal `@()` it compared the array's address with a fresh allocation, so
`a==@()` was false for every empty `a`, and between two named arrays it compared
the elements' bytes as a C string, so `@(256)==@(512)` was true. The fix is
present only when one operand is the literal `@()` and the other is an
identifier of array type, in either order: it is the whole comparison
rewritten, `"x.len==0"` for `x==@()` or `@()==x` and `"x.len!=0"` for `!=`,
which substitutes in place because `.len` binds tighter than any operator. Two
named arrays, a handle, a str, a map, `@()` against `@()`, and an array operand
that is not an identifier (a field, a call, an index) get no fix: element-wise
comparison is not a rewrite the compiler can choose, and `.len` is not the test
for a handle or a str.

### E4034 -- Field access on a layout the compiler cannot establish

| Field | Value |
|-------|-------|
| **Code** | E4034 |
| **Stage** | type_check (emitted by codegen) |
| **Severity** | error |
| **Message** | `no struct in scope declares a field '<f>', and the type of this value is not established` / `field '<f>' is declared at different offsets by more than one struct, ...` |

**Notes:** Stories 127.86 / 127.89 / 136.28. Lowering used to answer an

## Arena Errors (5xxx)

### E5001 -- Value escapes arena scope

| Field | Value |
|-------|-------|
| **Code** | E5001 |
| **Stage** | arena_check |
| **Severity** | error |
| **Message** | `value escapes arena scope: a <type> assigned inside an {arena} block to module-level '<name>' outlives the block` |
| **Fix field** | absent |
| **Conformance test** | D770, D771, C2250 (D772, D773: shapes that must not report it) |

**Notes:** A value that escapes an `{arena ...}` block (`memory-model.md`
§2.4). The checker's rule: inside the block, at any depth, a value of a heap
type (`str`, array, map, struct or sum, closure, or an error union whose value
is one of these) assigned to a module-level `mut` binding. `got` is the
value's type. Not E5001: a scalar assigned to a module-level `mut`, a store to
a binding of the enclosing function, a value whose type the checker leaves
unresolved, and anything outside an `{arena}` block. A module constant or
immutable `let` cannot be assigned at all (E4070). `{arena}` releases nothing
today (`memory-model.md` §1.2), so no escape leaves a dangling reference; the
full rule, and whether an escape is rejected or copied out, belongs to the
`{arena}` ADR (127.525). No `fix`: the repair (a binding inside the block, or
the store moved out of it) depends on the program. Emitted since story
127.526; before it the checker never reached the block's statements.
```text
m=test;
let g=mut."";
f=keep(n:i64):i64{{arena g="n=\(n)"};<0};
```
