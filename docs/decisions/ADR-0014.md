**Date:** 2026-07-03
**Status:** **DEFERRED to v0.5** (2026-07-07). 123.5 has landed, so this is now
decidable — and the decision is to *not* add option/non-null as a first-class type
before the from-scratch 1B model trains. The shipped **RT005 nil-deref trap**
already closes the crash/corruption class (nil-deref, map-miss, unwrapped-`$none`);
a first-class type is the one change that would grow the ~55-char / ~14-keyword
grammar the model must memorize, for a class the runtime already guards. Keep the
`T!$none` convention + RT005 for v0.4; revisit for v0.5 once the grammar is frozen
and the model exists.
**Deciders:** Matt Watt
**Story:** split out of ADR-0012(d) by the 2026-07-03 correct/secure-by-default ratification (Epic 124)

## Context

ADR-0012 (spatial safety) ratified a **runtime nil-deref trap** (RT005) now — a
source-invisible guard that converts a nil struct-field dereference (including the
map-miss-returns-0 and unwrapped-`$none` cases) into a loud trap instead of a
segfault. That closes the *crash/corruption* class immediately.

It deliberately **did not** make option/non-null a first-class *type* in the same
cycle, for two reasons the 2026-07-03 review made explicit:

1. **It is the one change that would grow the source grammar.** A first-class
   `$option`/`$some` or `T?` / non-null annotation adds surface to the ~55-char,
   ~14-keyword grammar that the from-scratch 1B model must *memorize*. Every other
   safety decision in the correct/secure-by-default program (ADR-0010/0011/0012/0013)
   lives out-of-band or in codegen and costs **zero** source tokens; this one does
   not, so it must be measured against the memorizability thesis, not assumed.
2. **The substrate is currently buggy.** The option convention today is
   `T!$none` reusing the error-union machinery (`stdlib/option.tki` — "no new type
   system machinery"), and that machinery **miscodegens**: `mt find(0){$ok:v v;$none:e 42}`
   returns `0`, not `42` (`known-limitations.md` §5, Epic 123.5). Building
   compile-time option/non-null enforcement on top of codegen that silently returns
   wrong values is how you manufacture a *new* corpus-corrupting bug — the exact
   root-of-trust failure the program is built to avoid.

## Decision (proposed — to be designed once unblocked)

When 123.5 has fixed the `$none`-arm codegen (verified: the `$none` arm returns its
value), design null-safety-by-construction **reusing the existing `T!$none` union +
`mt` match machinery** — i.e. a *type-checker + lowering* change, **not** new syntax:

- The type checker rejects a dereference / field-access of an un-matched `T!$none`
  (you must `mt` on it first), the same way it already enforces error-union handling.
- Codegen lowers the checked form correctly (contingent on 123.5).
- **Introduce a distinct `$some`/`$option<T>` or `T?` sigil ONLY if measurement shows
  the bare `$none` convention is ambiguous for the model** — and only after
  quantifying the added `--min` token cost and grammar-surface growth against the
  memorizability thesis. Default bias: reuse existing surface; add none.

## Consequences

- Null-safety becomes a *compile-time guarantee* (like the error-union `!` today),
  not a convention — the enterprise-grade / "safe by default" posture extends from
  spatial + temporal safety (ADR-0012 + the arena model) to value safety.
- Contingent, hard gate: **123.5 must land first.** This ADR stays Proposed until then.
- If a new sigil is ever added, it is the single place the correct/secure-by-default
  program touches the source-token budget — so it requires an explicit
  memorizability/`--min` measurement in the deciding revision of this ADR.

## Decision needed

Ratify the *direction* (null-safety by construction, reusing `T!$none`+`mt`, no new
syntax unless measurement forces it) now if desired, but **implementation is blocked
on 123.5**. The concrete type-checker/codegen design + the "new sigil or not"
measurement land in a follow-up revision once unblocked.
