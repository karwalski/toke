## 1. The problem

`docs/spec/memory-model.md` §1.1 says every function body has an arena and §1.3 says the whole arena is freed when the scope exits. Neither is implemented. Every runtime-created string, array, map and struct box comes from `malloc` or from the S1 sealed-string heap, and generated code frees almost none of it. `{arena}` parses and type-checks (E5001 rejects an assignment to a module-scope name inside one), and `NODE_ARENA_STMT` lowers to its body with comment markers. A program's resident set therefore grows with the total bytes it ever allocated. For a server, or for `ooke serve`, that means unbounded growth.

### What ships today

| Allocation | Where it comes from | Freed? |
|---|---|---|
| String literal | `@.str.N` constant | never (static) |
| Converted string producer (concat, interpolation, `slice`, `trim`, `split`, `file.read`, ...) | S1 sealed heap: one 16 GiB reservation, bump by atomic `fetch_add`, side bitmap (`runtime-abi.md` §3.1) | **never, by rule**: "a sealed string is never written, freed or reallocated" |
| Unconverted string producer (`str.fromint`, `str.fromfloat`, `json` strings, ...) | `malloc` | never, except the slice in section 6 |
| Array, `[byte]` | `malloc`, header `rc | cap | len` (ADR-0006) | never. `rc` is monotonic and only decides copy-on-write |
| Map, struct/sum box | `malloc` | never |
| Error box | per-thread buffer (127.109) | reused |
| Closure environment | `malloc` | released at the binding's exits when its count reaches zero (124.0c, `compute_closure_releases`) |
| Builder buffer (`str.builder`) | `malloc`/`realloc` | the buffer is never freed. `build` returns a sealed copy |

### Measured with the Z77 template harness

The harness is ooke's `template.tk` driven by a loop (source in section 8). It builds a 64,792-byte page with 104 `{= name =}` tags, then lexes it (`lex`), or lexes and renders it (`render`), `ITERS` times. Counters come from a scratch build only: a destructor that prints `tks_top` (sealed-heap bytes handed out) and a `DYLD_INSERT_LIBRARIES` interposer that counts `malloc`/`calloc`/`realloc` calls, bytes and `free`s. Neither is committed. Toke base `a4636b56`, ooke `d0dde52`, macOS arm64.

| mode, iterations | sealed-heap bytes | malloc calls / bytes | frees | peak RSS (`/usr/bin/time -l`) |
|---|---|---|---|---|
| lex, 20 | 4,734,896 | 4,661 / 194,831 | 14 | 6 MB |
| lex, 200 | 16,718,576 | 44,801 / 1,598,831 | 14 | 20 MB |
| lex, 2000 | — | — | — | 126–150 MB |
| render, 20 | 8,516,656 | 11,203 / 4,392,138 | 194 | 12 MB |
| render, 200 | 54,536,176 | 110,203 / 43,551,138 | 1,814 | 71 MB |
| render, 2000 | — | — | — | 128–288 MB |

Per iteration, lexing allocates 66.6 KB of sealed strings (the token texts, about one page) and 7.8 KB of arrays. Lexing plus rendering allocates 255.7 KB sealed and 217.7 KB malloc'd, or 7.4 times the 64.3 KB page it produces, with about 9 frees. **No byte allocated in an iteration is live after it.** The loop keeps only an integer. A per-iteration region would therefore recover all of it. Peak RSS at 2000 iterations varies by a factor of two between identical runs, because macOS compresses idle pages. So RSS is a poor gate and allocation counters are a good one (section 7).

## 2. Option A — per-function arena with escape analysis on returns and stores (the spec as written)

Each function gets a region at entry and releases it at every exit. §2.3 says a returned value is "copied into the caller's arena", and §2.4 says anything else that would outlive the region is rejected (E5001).

What it would need:

1. **Copy-out at every return of an allocated value.** The copy is deep: a `@$token` returned by `tpllex` holds 208 token strings, and returning it copies the array, each struct box and each string. In a call chain the copy happens once per level, so depth × size. 127.236 measured that 1,921 of 1,946 struct/sum literals in the corpus sit in a `<` return. The return slot it proposes (an sret destination owned by the caller) is how A avoids most of that copying: the callee builds the value straight into the caller's region. A and 127.236 should be designed together.
2. **Every store that outlives the function is an escape.** This covers an assignment to a parameter-derived or outer value, `append`/`set` onto an array the caller owns, `put` into a caller's map, a struct field of a caller's struct, a module global, a closure capture (§2.5 already heap-allocates the environment, but its captured strings would then point into a dead region), a value handed to `sc`/`task` spawn (§3.2 says it is copied; whether the runtime does is not verified here), and a value handed to C code that keeps it (below). Each case must be either rejected with E5001, which would reject large amounts of accepted code, or copied into the destination's region, which means the runtime has to know which region every block belongs to.
3. **C code that keeps toke pointers.** The router stores route strings, `http` keeps handler state, `llm` client structs share their string fields (`llmtool.withtools`), `vecstore` keeps entries, and the html/svg trees own their strings. `.tki` files already carry an `ownership` field (§4.4), but nothing enforces it. Under A each such parameter has to be marked "retained", so that codegen copies the argument out of the region first. That requires an audit of every module.
4. **S1.** The sealed heap is one process-wide bump region shared by every thread, and its rule is that a sealed string is never freed. A per-function region would need either a sealed heap per region (a per-thread region stack, each with its own range of bitmap bits, cleared on release), or a region outside the sealed heap, which gives up S1's O(1) length for every string the function makes. The owner's answer names this conflict.
5. **ADR-0006.** `rc` is monotonic because nothing is ever released, so an over-count only costs a copy. Region release does not need `rc`. The danger is the in-place path: `x = x.append(v)` with `rc == 1` grows `x`'s block, and if `x` belongs to an outer region, the grown block must be allocated there too, or `x` must count as escaping. The linear-array analysis (`la_*` in `llvm.c`) must learn about regions.

Correctness risk: very high. Every missed escape is a use-after-free that shows up far from its cause, and the copies make the common return path slower. This option is not a candidate for a first slice.

## 3. Option B — scope-exit frees of non-escaping temporaries

Codegen frees individual values at the end of the statement, loop iteration or function that holds the last reference to them. This is closer to Perceus/ADR-0006 D1 than to an arena.

Proof obligations for each freed value:

- **P1, no other holder.** No name, store, argument that C keeps, return, capture or spawn holds the value after the free point.
- **P2, fresh.** The producer returned memory it allocated for this call: not a literal, not one of its arguments, not a pointer into an argument, not a cached value. Core producers are fresh today (`str_trim`, `str_slice`, `trimprefix` always `tks_dup`). But a match arm or `if` expression can yield an existing value: in ooke's `tplexprctx`, `mt str.slice(..) {$ok:v v;$err:e trimmed}` yields the live local `trimmed` on its error arm. Freshness is a property of the whole expression, not of the call.
- **P3, freeable.** Only memory from `malloc` can be passed to `free`. Every converted producer returns a sealed string, and S1 forbids freeing one. A sealed temporary could only be reclaimed by a rewind of the bump pointer, and only when it is the newest allocation (a CAS from `top == p_end` to `p_start`, clearing its bit and re-poisoning it under ASan). In the common case of `str.trim(s.slice(a;b))`, the consumer allocates its own result after the temporary, so the temporary is not on top any more and the rewind reclaims nothing. A real sealed free list is a change to S1's rule, so it is the owner's to make.

So B, beyond section 6, needs an alias/freshness analysis (P1, P2) and an S1 change (P3). Without those, no general "free the temporaries of an expression statement" slice is provably safe. The candidates considered and rejected:

| Candidate | Why not now |
|---|---|
| `s.slice(..)` / `str.trim(..)` result consumed in the same expression by a non-retaining reader (`indexof`, `==`, `.len`, `startswith`) | sealed (P3); the free-if-top rewind fails whenever the consumer allocates; freshness through `mt`/`if` arms (P2) |
| Loop-local `let` temporaries | needs P1 over the loop body: appends, map puts, struct fields, assignment to outer `mut` names, C retention |
| `str.builder` buffer after `build` | the builder is a value that can be added to and built again; freeing at `build` needs P1 on the builder handle |
| Interpolation's u64 ≥ 2^63 helper strings | the value is a `select` of two conversions plus a sealed join. It can be freed, but each arm must be freed separately; left for later (it is rare) |
| `tk_str_concat` chains | none to free: `$str+$str` is a type error (ADR-0004), and interpolation is a single `tk_str_join_n` since 127.26 |

## 4. Option C — the explicit `{arena}` block (the owner's first target)

`{arena ... }` already exists in the grammar (`grammar.ebnf` `ArenaStmt`) and in the checker (E5001 for a module-scope assignment). The idea is to give it real semantics: everything allocated while the block runs goes to a region that is released when the block exits. A server wraps its per-request handler in one, and an ooke render loop wraps each page.

Why it comes first:

- The programmer states the lifetime, so the compiler checks that boundary instead of inferring every function's.
- The escape surface is the block's own exits: assignments to names declared outside it, appends/puts/field-sets on outer values, `<` inside the block, captures, spawns, and C retention. The checker can enumerate these syntactically. E5001's existing walk (`types.c`, `arena_depth`) is the place to extend.
- On the Z77 harness one block around the loop body recovers every byte (section 1).

What it still needs, and what the ADR must settle (127.525):

1. **The sealed-heap region.** One option is a mark/release on a per-thread sealed sub-heap: mark the bump pointer at entry, and at exit clear the bitmap bits of `[mark, top)`, re-poison them, and reset `top`. That works only if no other thread allocated in between, so it needs a per-thread heap (a change to S1's single `fetch_add`) or a per-region sub-range. S1's rule then becomes: "a sealed string is never freed **except by the release of the region that holds it**".
2. **malloc'd blocks** (arrays, maps, boxes, unconverted strings) need a region allocator behind `tk_arr_alloc`, the inlined array-literal `malloc` in codegen, and every glue `malloc` that hands a block to toke. The census in `runtime-abi.md` §3.1 is the model for that inventory.
3. **C retention.** The same `.tki` "retained" marking as option A, but needed only for calls made inside a block.
4. **What `{arena}` and E5001 mean afterwards.** The amendment (127.524) must state this either way.

## 5. Option D — reference counting with release (ADR-0006 D1); option E — the shipped model plus a leak budget

D frees at the last reference and is the general answer. ADR-0006 rejected it on risk ("a use-after-free minefield"), and it also needs S1 to free sealed strings. Nothing new here changes that judgement.

E is answer (b): amend §1.1, §1.3 and §2.3 to say that runtime-created values live until the program exits (except closure environments and the compiler temporaries of section 6), and state a leak budget per workload. 127.524 is that amendment. It is needed whatever (a) becomes, because the spec currently promises behaviour that does not ship.

## 6. The slice that ships: interpolation frees its own number conversions

**What changed (`src/llvm.c`, `NODE_STR_LIT` and `emit_int_to_str` / `interp_render`).** In `"k\(i)=\(x)"` each number segment is converted by `tk_str_fromi64_w` or `tk_str_fromfloat_w`, which return `str_from_int` / `str_from_float` blocks: a fresh `malloc(24)` / `malloc(64)`. All parts go to a single `tk_str_join_n`, which copies them into a new sealed string. The conversions were never freed. Lowering now records, for each segment, the SSA temp of the conversion it emitted itself. After the join it emits `call void @free(i8* %tN)` for exactly those temps.

**Why it is provably safe:**

- *P1.* The temp is an SSA value that codegen created. No toke name is bound to it, and its only use is as an argument of the join. The join returns a new block (`tks_alloc` + `tks_seal`), copies every part with `memcpy`, and keeps no pointer to any part.
- *P2.* `str_from_int` / `str_from_float` always `malloc` (or return NULL, and `free(NULL)` is a no-op). Neither returns a literal, a cached value or a sealed string. A temp is recorded only when the segment's final value **is** the conversion (an SSA-number match), so an operand rendered any other way is never freed: a string (the caller's value), a bool (a literal), or a u64/u8/u16/u32 (a `select` between the conversion and a sealed join).
- *P3.* The temp comes from `malloc`, so `free` is legal, and S1 is not involved. This holds only while `str_from_int` / `str_from_float` stay unsealed. Both now carry a comment that says so, and C2200's ASan run reports a bad free if a later S1 tranche converts them without removing the free.
- *Not the result.* A one-segment literal (`"\(n)"`) returns its conversion, so nothing is freed there (the `nvals == 1` branch).
- *Dominance.* The conversion is already an operand of the join, so it dominates the join. The frees follow the join in the same block, so control flow inside a segment (an overflow-check branch, an `if` expression) cannot break it.
- *Spec surface.* §1.5 ("no mechanism to free a single allocation") concerns toke programs and is unchanged. These temps never reach toke code, so `runtime-abi.md` §3's "nothing may free() one that reached toke code" also still holds.

**Tests.** C2200 asserts the IR shape (which segments are freed, each free right after the join that took that temp, nothing freed on the u64 path), plus exact output under ASan+UBSan with `TK_STR_VERIFY=1` for every operand shape. Negative controls: a scratch `tkc` that also frees the one-segment conversion fails with `heap-use-after-free` (a READ in `puts` from `tk_io_println_w`); the base fails the IR check and passes the run.

**Measured (same machine, three to five runs each, medians).**

| Program | Base `a4636b56` | With the slice |
|---|---|---|
| 1M × `"k\(i)=\(i*3);f=\(1.5)"` (scratch micro), peak RSS | 154.9 MB | **32.3 MB** |
| same: malloc calls / bytes / frees | 3,000,198 / 112,037,533 / 14 | 3,000,198 / 112,037,529 / **3,000,015** |
| same: output, time | `total=20518516`, 0.26 s | identical, 0.27 s |
| Z77 harness, render 20: sealed / malloc bytes / frees | 8,516,656 / 4,392,138 / 194 | 8,516,656 / 4,392,162 / 196 |
| Z77 harness, render 20 / 2000 peak RSS | 12 / 128–288 MB | 12 / 187–244 MB (no change outside noise) |

The harness does not improve, and that is expected: its bytes are token slices and builder output, i.e. the sealed strings and arrays that sections 3 and 4 cover, and only its final `println` interpolates a number. The slice targets the other common shape: log lines, keys and messages built from numbers in a loop.

## 7. Measurement plan for the next slices

1. **Harness.** The Z77 harness in section 8 runs at 20, 200 and 2000 iterations in `lex` and `render` modes, against the candidate and the base built from the same tree.
2. **Primary metric: bytes per iteration, not peak RSS.** Take the slope of (sealed-heap bytes + malloc bytes − freed bytes) between 200 and 20 iterations. A region slice that works makes the slope zero for the code inside the region. Peak RSS is reported as well but does not gate (it varies 2× on macOS at 2000 iterations). For the counters, a committed `TK_MEM_STATS=1` exit report in `str.c` / `tk_runtime.c` should replace the scratch interposer. That is a small runtime story to file with 127.525, not part of this note.
3. **Safety.** Each slice ships a C-series case that, like C2200, asserts the frees in the IR and runs the program and the stdlib under ASan+UBSan with `TK_STR_VERIFY=1`. A negative control (a deliberately over-eager free) must fail it. Region releases also need a case for every escape route in section 4: outer assignment, append, put, field, return, capture, spawn and C retention.
4. **Gates.** `make conform` at 100%; `make test-asan-compiler`; ooke `make check-toke-candidate` and `make test`; and the website's `make check-toke`, all against the candidate.

## 8. The harness

`test/z256bench/test_z256bench.tk` in a scratch ooke worktree, run through ooke's `test/run_tests.sh z256bench` (which links ooke's module IR), then `Z256_MODE=lex|render Z256_ITERS=N /usr/bin/time -l build/testbin/test_z256bench`.

```
m=test.z256bench;
i=tpl:ooke.template;
i=str:std.str;
i=io:std.io;
i=env:std.env;
f=page():$str{
  let filler="<div class=\"row\"><p>Lorem ipsum ... (an ~600-byte paragraph) ...</span></div>\n";
  let s=mut."";
  lp(let i=0;i<104;i=i+1){ s="\(s)\(filler)<b>{= name =}</b>\n"; };
  <s
};
f=main():i64{
  let src=page();
  let ctx=@("name":"World");
  let iters=env.getint("Z256_ITERS";20);
  let render=env.getor("Z256_MODE";"render")=="render";
  let total=mut.0;
  lp(let k=0;k<iters;k=k+1){
    let tokens=tpl.tpllex(src);
    let toks=mt tokens {$ok:t t;$err:e @()};
    if(render){
      let out=tpl.tplrender(toks;ctx;"/tmp";@());
      let s=mt out {$ok:s s;$err:e ""};
      total=total+str.len(s);
    }el{ total=total+toks.len; };
  };
  (io.println("page=\(str.len(src)) rendered_total=\(total)"));
  <0
};
```

## 9. Questions for the owner

1. For the `{arena}` ADR (127.525): should S1's rule become "never freed except by the release of the region that holds it", with a per-thread sealed sub-heap? Or should `{arena}` allocate strings outside the sealed heap and give up O(1) length inside the block?
2. Is E5001 inside `{arena}` a rejection (strict, but it breaks code that appends to an outer array inside a block) or a copy-out (permissive, slower, and it needs region-aware allocation)?
3. Should the `.tki` `ownership` field become load-bearing (a "retained" parameter marking that codegen honours), audited module by module like the S1 census?
4. Should option A (per-function arenas) be designed together with 127.236's return slot, or dropped from the spec in favour of `{arena}` plus the amendment?
