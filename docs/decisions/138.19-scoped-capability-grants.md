**Date:** 2026-11-10
**Status:** **proposed** — a spec amendment to [the capability model](/docs/spec/capabilities/) and an extension of [ADR-0010](/docs/decisions/ADR-0010/). **Not implemented. Implementation is blocked on owner review of this proposal.**
**Story:** 138.19 (loke handoff 2026-09-27, T-59 / B9; listed as OPEN in `docs/loke-handoff-2026-09-27-reply.md`)
**Decisions needed from the owner:** five, listed in [Decisions for the owner](#decisions-for-the-owner) at the end.

## The problem

ADR-0010 made authority explicit: a toke program has no file-system, network, environment-write or process-spawn authority unless it is granted. Every grant today is a **whole class**:

- `--allow-read=/srv/www` grants `fs.read` for **every** path. The value is accepted and ignored. `src/stdlib/capabilities.c` (`flag_to_caps`) and `src/main.c` both compare only the flag's prefix.
- In `tkc.toml`, `fs_read = "/srv/www"` reads as `true` (`src/config.c`: any non-empty quoted string is truthy). The spec warns about this in §2.2: *"Write `true`, not a path, so the manifest does not claim a restriction the binary does not have."*
- `net` is one grant that covers listening on any port **and** connecting to any host.
- A launcher can add `--allow-*` flags at run time. The flags are unioned with the baked set, so a binary shipped with narrow grants can be widened by whoever starts it.

loke grants `fs_read`, `fs_write`, `net` and `process_spawn` as bare `true`, with the intended scope written in a comment, and measures its grants in its own gate (`scripts/check_capabilities.sh` in loke). It needs those comments to become enforced grants.

## What exists today (the enforcement point)

The design changes as little as possible of what already works:

| Piece | Today | File |
|---|---|---|
| Grant set | one `uint32_t` bit set, five classes | `src/stdlib/capabilities.h` |
| Gate | `TK_REQUIRE(cap)` at the top of every acquisition wrapper (open, listen, connect, spawn, setenv): 33 `fs.read`, 21 `fs.write`, 14 `net`, 2 `env.write` and 3 `process.spawn` sites as of 2026-11-10 | `src/stdlib/*.c` |
| Denial | `tk_cap_deny` prints CAP001 (plus a JSON line under `TK_DIAG_JSON`) and calls `exit(1)` before the syscall | `capabilities.c` |
| Baking | the compiler emits strong `@__tk_cap_baked_{grants,present,enforce}` constants that override weak defaults | `src/llvm.c`, `capabilities.c` |
| Manifest | `tkc.toml [capabilities]`, a line parser that takes `key = true/false/"string"` | `src/config.c` |
| Runtime flags | `tk_cap_init` parses `--allow-*` from the raw argv, and `tk_runtime_init` strips them so the program never sees them | `capabilities.c`, `tk_runtime.c` |
| Coverage gate | `scripts/check_capability_sinks.py` (conformance case **C470**) walks every callable stdlib entry to every fs/net/env/spawn primitive. It fails when a path reaches a primitive with no `TK_REQUIRE` of the right class. | story 121.22 |
| Record | `--companion` writes the baked grant set into `.tkc.md`, and `--show-limits` prints it | `src/companion.c`, `src/main.c` |

Checking at the point of acquisition (Deno semantics) stays. A scoped check happens at the same `TK_REQUIRE` sites, which are the only places that hold the path, host or command.

## Proposal

### 1. Grant syntax

A grant is either a **whole class**, as today, or a **list of scopes** for that class. The class set does not change: five classes, as ADR-0010 has them.

| Class | Scope form | Matches |
|---|---|---|
| `fs.read`, `fs.write` | a path: `/srv/www`, `./content`, `~/.config/loke` | the path itself and everything beneath it, compared **component by component** after canonicalisation (§3.1). `/srv/www` does not match `/srv/wwwx`. |
| `net` | `connect:HOST[:PORT]` or `listen:ADDR:PORT` | `HOST` is a DNS name, `*.example.com` (one or more labels, never the bare apex), an IPv4/IPv6 literal, or a CIDR block. `PORT` is a number or `*`, and an omitted connect port means any port. `listen:` needs an explicit address, so `listen:0.0.0.0:8080` is visibly different from `listen:127.0.0.1:8080`. |
| `process.spawn` | a command: `/usr/bin/git` or `git` | the executable that would run, after `PATH` lookup (§3.3) |
| `env.write` | a variable name: `TZ`, `LANG`, `TOKE_*` | the key passed to `env.set` / `os.setenv`, with one trailing `*` as a prefix wildcard |

`net` gets its direction inside the scope (`connect:` / `listen:`) rather than becoming two classes. That keeps ADR-0010's five classes and the existing `net = true` meaning, and still gives loke what T-59 asks for: listening and connecting become separate grants.

**Command line**, at compile time (baked) or run time:

```sh
tkc app.tk --allow-read=./content,/etc/ssl/certs --allow-write=./cache \
           --allow-net=connect:api.example.com:443,listen:127.0.0.1:8080 \
           --allow-run=/usr/bin/git --allow-env=TZ -o app
```

A flag may be repeated, and scopes accumulate. A flag with no `=value` is the whole class, as today. `--allow-all` is unchanged.

### 2. Manifest form

`tkc.toml [capabilities]` accepts a TOML array of strings for each class:

```toml
[capabilities]
fs_read       = ["./content", "/etc/ssl/certs"]
fs_write      = ["./cache"]
net           = ["connect:api.example.com:443", "listen:127.0.0.1:8080"]
process_spawn = ["/usr/bin/git"]
env_write     = ["TZ"]
# runtime = "narrow"   # see 4 below
```

- `true` / `false` keep their meaning: the whole class, or nothing.
- A **single quoted string** becomes a one-element scope list. Today it is silently the whole class (spec §2.2). This is the only change in meaning, and §5 covers it.
- `config.c` is a line parser. It gains single-line arrays only (`[ "a", "b" ]` on one line, with no nesting and no trailing comma), which keeps the parser small. Anything else is a parse error that names the line, as today.
- The `.tkc.md` grant record that `--companion` writes, and `--show-limits`, list the scopes under each class.

### 3. How the broker enforces a scope

`capabilities.h` gains a scoped gate next to `TK_REQUIRE`. Each sink passes the value it is about to use:

```c
TK_REQUIRE_PATH(TK_CAP_FS_READ, path);          /* file / dir / db / template readers */
TK_REQUIRE_PATH(TK_CAP_FS_WRITE, path);
TK_REQUIRE_NET(TK_CAP_NET_CONNECT, host, port); /* client connect, after URL parse  */
TK_REQUIRE_NET(TK_CAP_NET_LISTEN, addr, port);  /* bind / listen                    */
TK_REQUIRE_CMD(argv0);                          /* spawn / exec / spawndetached     */
TK_REQUIRE_ENV(key);                            /* env.set / os.setenv              */
```

`TK_CAP_NET_CONNECT` and `TK_CAP_NET_LISTEN` are **sub-bits of the `net` class**: `net = true` sets both. The broker keeps, for each class, either "whole class granted" or a sorted scope list. Scopes are parsed and canonicalised once, in `tk_cap_init`, never on the hot path. A scoped check is a linear scan of a list the size of the manifest, which is small and runs once per acquisition. It is not per read or write.

**3.1 Paths.** The broker resolves the requested path with `realpath()` on its longest existing prefix, then appends the components that do not exist yet. A file being created inside a granted directory therefore passes, and a `..` or a symlink that escapes the directory fails. Granted paths are canonicalised the same way at start-up. A relative grant resolves against the **working directory at process start**, as Deno does. `~` expands from `HOME` at start-up. The comparison is by whole path components. The residual race is check-then-open: a path component swapped for a symlink between the check and the `open`. It is accepted and documented, as Deno accepts it. Closing it needs `openat2(RESOLVE_BENEATH)` on Linux or a descriptor-relative walk elsewhere, which can follow later without changing the syntax.

**3.2 Hosts.** A connect scope is matched against the **name the program passed**, before DNS resolution. An IP or CIDR scope matches only an IP literal. A name grant does not cover whatever addresses the name resolves to: that would invite DNS-rebinding confusion. When the HTTP client follows a redirect, each hop is a new acquisition and is checked again. `listen` matches the exact bind address and port, and the `net.listen` shorthand that takes only a port binds `127.0.0.1` (`net_glue.c`), so it matches `listen:127.0.0.1:PORT`. `net.portavailable` binds, so it is a listen check.

**3.3 Commands.** For an argv[0] containing `/`, the broker canonicalises it and compares it with absolute grants. For a bare name, the broker performs the same `PATH` search `execvp` will perform, then compares the resolved absolute path. A bare-name grant (`git`) is resolved against `PATH` **once, at start-up**, and pinned. `process.exec` and `process.spawndetached`, which split a command string, check the first token. Only the executable is scoped, not its arguments. Argument scoping is out of scope: see the threat model.

**3.4 A class-only gate under a scoped grant fails closed.** A sink still gated by the plain `TK_REQUIRE(cap)` passes only when the **whole** class is granted. A program with `fs_read = ["./content"]` that reaches an unconverted reader gets a denial, never silent access. C470's checker is extended so that every sink that holds a path, host, command or key must use the scoped gate. The class-only form remains legal only on the checker's skiplist, which already self-fails when a line is stale. The implementation converts every listed sink in the same change, so the skiplist starts empty.

**3.5 Diagnostics.** When the class is not granted at all, the error is **CAP001**, with the same text and JSON as today. When the class is granted but not for this scope, the proposal is a new code, **CAP002** (see [decision D3](#decisions-for-the-owner)), whose JSON line carries `"capability"` and `"scope"` (the canonical path, `host:port`, command or key). Error codes are stable: CAP001 keeps its meaning, and CAP002 is new. The `fix` field names the **exact** scope that would admit the call (for example `fs_read = ["/srv/www/data.json"]`). That fix is deterministically sufficient. Whether it is wise is the reviewer's call, so the message suggests the narrowest grant and never the class.

**3.6 Baking.** The compiler emits one more strong constant pair, `@__tk_cap_baked_scopes` (an array of `{class, kind, string}`) and `@__tk_cap_baked_nscopes`, with weak empty defaults in `capabilities.c`. A binary built before this change links and behaves exactly as now.

### 4. Runtime flags may narrow, not widen

The threat model at §6 makes the union rule the largest hole, so the proposal changes it, as an owner decision (D2). A binary that **bakes any grant set** treats runtime `--allow-*` flags as a **narrowing**: the effective grant is the intersection of the baked grant and the runtime grant. The manifest can opt back into today's union with `runtime = "union"`. A binary with **no baked grants**, which is how scripts are run during development, keeps today's behaviour: the runtime flags are the grant. `--allow-all` at run time on a binary with a baked set is refused with a one-line message, unless `runtime = "union"` is set.

### 5. Compatibility with today's whole-class flags

| Today | After | Breaks? |
|---|---|---|
| `--allow-read`, `fs_read = true`, `--allow-all`, `all = true` | unchanged: whole class | no |
| `--allow-read=/srv/www` (value ignored, whole class) | scoped to `/srv/www` | **yes**, for a program that relied on the ignored value granting more |
| `fs_read = "/srv/www"` (truthy, whole class) | scoped to `/srv/www` | **yes**, same case |
| a launcher's `--allow-net` widening a baked set | refused, or intersected | **yes**, by design (§4) |
| a binary built before the change | no scope table; behaves exactly as today | no |
| `enforce = true/false`, `--cap-enforce` | still accepted and vestigial (spec §2.2) | no |

The first-party manifests (ooke, website) and the grant-aware harnesses compile with `--allow-all` (spec §4), so they are unaffected. Before implementation lands, one release prints a compile-time warning for every quoted-string grant, telling the author it will become a scope. The warning gets the next free W-series code, allocated at implementation and not here. That gives anyone who wrote a path expecting the whole class one release to notice.

### 6. Threat model

**In scope (what scoped grants defend):**

- LLM-generated or third-party toke code that over-reaches with granted authority: reading `~/.ssh` or `~/.aws` under a grant meant for `./content`; writing outside its cache; sending data to a host it was not meant to talk to; spawning a shell when it was granted `git`; listening on `0.0.0.0` when it was meant to serve loopback.
- The confused deputy: a server that builds a path from request input (`../../etc/passwd`) or follows a redirect to an internal host. The scope check sees the final canonical path or host.
- Supply chain: an imported toke module that tries authority the application's manifest does not name.
- A launcher widening a shipped binary's authority (§4).

**Out of scope (not defended, and the spec says so):**

- **Native code.** A user `extern` C function (C112) and any C FFI call the program's own native code makes do not go through the broker. Scoped grants are a **policy layer in the toke standard library**, not an OS sandbox. Hard isolation needs the OS: Landlock or seccomp on Linux, `sandbox-exec` on macOS. Compiling the baked scopes into Landlock rules is a natural follow-up (D5), not part of this story.
- Memory-safety bugs in the program or runtime that let code skip the gate.
- The check-then-open race (§3.1).
- DNS answers: a granted name may resolve anywhere (§3.2).
- Process arguments: `git` granted means `git` with any arguments.
- An attacker who controls the binary, its baked constants, or the environment it starts in (`PATH`, `HOME`, the working directory).
- Reads of the environment, and reads or writes on a handle acquired under a grant. Both are ungated today, by design.

### 7. Test plan

Conformance numbers are allocated when the implementation is scheduled. Every case runs both on the build that introduces the feature and as a negative control on the build before it.

1. **Paths:**
   - an `fs.read` scope admits a file inside it and denies one outside it
   - `..` escapes are denied
   - a symlink inside the scope that points outside it is denied
   - a prefix-confusion case (`/srv/www` versus `/srv/wwwx`) is denied
   - a trailing slash and a relative grant behave the same
   - `~` expands
   - creating a new file inside an `fs.write` scope is admitted
   - a reader that takes a directory (`http.servedir`, `file.list`) is checked on the directory
2. **Network:**
   - a `connect:` scope admits its host and port and denies another host and another port
   - `*.example.com` admits `a.example.com` and denies `example.com` and `evilexample.com`
   - an IP literal is matched against a CIDR scope
   - a `listen:` scope admits its address and port
   - a connect-only grant denies a listen and a listen-only grant denies a connect
   - an HTTP redirect to an unscoped host is denied at the hop
3. **Commands:**
   - an absolute grant admits that path and denies another binary of the same name
   - a bare-name grant is pinned at start-up, so changing `PATH` later does not widen it
   - `process.exec` with a command string is checked on its first token
4. **Environment:** a key scope and a `PREFIX_*` scope.
5. **Whole-class compatibility:**
   - `true`, `--allow-x` with no value, and `--allow-all` behave byte-for-byte as before. The existing CAP001 cases and the C470 suite are the regression set.
   - a binary built before the change still links.
6. **Runtime narrowing (§4):**
   - a runtime flag narrows a baked scope
   - a runtime flag cannot widen a baked scope
   - `runtime = "union"` restores the union
   - a binary with no baked grants takes its runtime flags as the grant
7. **Fail closed:** a scoped grant and a sink still on the class-only gate gives a denial, not access. C470 fails on a scope-bearing sink with a class-only gate, with a negative control that removes one conversion.
8. **Diagnostics:**
   - CAP001 and CAP002 JSON lines are schema-conforming
   - D-series cases assert CAP002's `fix` names the exact scope
9. **Manifest:**
   - `tkc.toml` arrays parse
   - a malformed array, an unknown scope prefix (`net = ["udp:..."]`) or an empty string is a parse error with its line number
   - `--show-limits` and the `.tkc.md` record list the scopes
10. **Downstream:**
    - ooke `make test` and the website build pass unchanged
    - loke's `scripts/check_capabilities.sh` passes once loke replaces its `true`-plus-comment grants with scope lists

## Decisions for the owner

- **D1 — Accept the grant syntax and manifest form** (§1, §2): direction-prefixed `net` scopes inside the existing five classes, rather than new `net_connect` / `net_listen` classes. *Recommendation: accept.*
- **D2 — Runtime flags narrow a baked set instead of widening it** (§4), with `runtime = "union"` as the opt-out. This is a behaviour change, and the main security gain after scoping itself. *Recommendation: accept.*
- **D3 — A new code CAP002 for "class granted, scope not"**, as opposed to CAP001 with an extra field. CAP002 lets the repair loop tell "add a grant" from "widen a grant". *Recommendation: CAP002.*
- **D4 — A quoted-string grant changes meaning from whole class to scoped** (§5), after one release of warnings. *Recommendation: accept.* The current meaning is a documented trap.
- **D5 — OS-level enforcement** (Landlock, seccomp, `sandbox-exec`) is a separate follow-up story, not this one. *Recommendation: file it after this story lands.*

Until these are answered, 138.19 stays **blocked: owner (review this proposal)**. No code changes with this note.
