**Deciders:** Matt Watt
**Story:** 116 Workstream A / A1

## Context

In v0.3 `if` was a statement only. To compute a value conditionally, idiomatic
toke declared a mutable flag and assigned it inside each arm:

```
let sign = mut.0;
if(n<0){ sign = 0-1 };
if(n>0){ sign = 1 };
```

The "toke-for-LLM foundations" audit (Epic 116) found this pattern pervasive in
the corpus and actively harmful for the language's purpose: it is more tokens, it
spreads one logical decision across several statements (hurting minimal-code-first
generation), and it fights the prior every base model already holds — in almost
every language a conditional is an expression. Constrained decoding and
from-scratch training both benefit from one canonical conditional-value form.

## Decision

`if` is an **expression** as well as a statement. In expression position it yields
a value and **requires** an `el` arm (a value must always exist). Each arm is a
block whose value is its tail expression; the two tails must unify to one type.

```
IfExpr = 'if' '(' Expr ')' Block ( 'el' IfExpr | 'el' Block ) ;
let sign = if(n<0){ 0-1 } el if(n>0){ 1 } el { 0 };
```

The statement form (value discarded, `el` optional) is unchanged. The idiom
standard (`idiom-v0.4.md`) makes expression-`if` the required form and the
rule-based judge penalises the mut-flag anti-pattern.

## Consequences

- Breaking only in the additive sense: existing statement-`if` still parses. New
  capability; no existing valid program breaks **from A1 alone**.
- Codegen: `NODE_IF_STMT` handled in `emit_expr` with `block_tail_expr` /
  `emit_if_branch_value`; `infer()` returns the then-branch tail type.
- Pairs with `&&`/`||` (ADR-0009 companion / A2) to eliminate flag-soup.
- Spec: [toke-spec-v0.4 §C](/docs/spec/toke-spec-v0.4/); grammar `IfExpr`.
