## The gap

The broker added by ADR-0010 and 138.19 is a **policy layer in the toke standard library**. It checks a grant at the point where authority is acquired, inside the stdlib wrapper. Code that does not go through a wrapper is not checked:

- a user `extern` C function, such as libc's `fopen`, declared in toke source (C112);
- any C FFI call the program's own native code makes;
- a stdlib sink whose gate a defect removed or never added. C470 guards against this, but only for the paths it can see.

The 138.19 threat model (§6) lists native code as **out of scope**. It names OS-level enforcement as the follow-up: Landlock or seccomp on Linux, `sandbox-exec` on macOS.

## Design

### Defence in depth, never a second policy

The OS layer is applied **after** the broker has computed the effective grants (baked grants, plus run-time narrowing or union under D2), at the end of `tk_cap_init`. That is before `main` and before any thread exists. The OS layer follows four rules:

1. **The broker is unchanged.** It still runs first at every gated sink, and it still gives CAP001 or CAP002 with the same text, JSON and `fix`. Every existing capability conformance case passes with the OS layer forced on (see Validation). The OS layer only adds denials for code that never reached a gate.
2. **The OS layer admits a superset of what the broker admits.** It never refuses a call the broker would admit. Where the kernel cannot express a scope, the OS rule for that access is widened or dropped, and **CAP004** says so. A kernel scope is never narrower than the grant.
3. **Off unless asked for.** A binary built without the opt-in has the weak default `__tk_cap_baked_os = 0`. Its IR is byte-identical to the IR it had before this change (C2230 case 4), and `tk_cap_init` never reaches the OS code.
4. **In `ALLOW_ALL` there is nothing to restrict.** Nothing is applied, and no diagnostic is given.

### The opt-in

| Where | Spelling |
|---|---|
| `tkc.toml` | `[capabilities]` `os_enforce = true` (`true` or `false`; anything else is a parse error naming the line) |
| `tkc` flag | `--cap-os-enforce` |
| Record | `--show-limits` prints `cap-os = 1`. The `--companion` record adds the line "OS-level enforcement: **on**". |
| Debug | `TK_CAP_OS_SHOW=1` in the environment of the compiled binary prints the generated profile or rules to stderr before they are applied. |

The key bakes `@__tk_cap_baked_os = constant i32 1`. Like `enforce`, it declares no grant. It sets `cap_present`, not `cap_set`, so it does not make run-time flags narrow (D2).

There is deliberately no run-time switch: the binary carries its own setting, as it carries its grants.

### What the kernel is told

The plan is built from the broker's own canonical scopes, after `realpath` resolution and after command names are pinned on `PATH`. For each access whose class is **not whole**:

| Access | Admitted by the OS layer |
|---|---|
| fs read | each `fs.read` scope (the path and everything beneath it), plus the read-only system baseline |
| fs write | each `fs.write` scope (beneath it), plus `/dev/null`, `/dev/zero`, `/dev/tty` (and, on macOS, `/dev/stdout`, `/dev/stderr`, `/dev/dtracehelper`; on Linux, `/dev/full`) |
| exec | each `process.spawn` command (the canonical executable). On Linux the dynamic-loader directories are added too, because the kernel opens a program's ELF interpreter for execution and Landlock checks that open. |
| listen | each `listen:` scope's **port**: loopback-only on macOS when the address is loopback, otherwise any address. Port 0 (ephemeral) means any port. |
| connect | each `connect:` scope's **port**: loopback-only on macOS for a loopback host. A scope that admits any port leaves connect unrestricted. |
| net not granted at all | no bind and no IPv4/IPv6 connect. On Linux a seccomp filter also refuses `socket(AF_INET/AF_INET6)` (UDP included) and `io_uring_setup`. |

A class granted **whole** gets no OS rule. `env.write` gets none on any platform, because it changes in-process memory.

Which source supplies the scopes under D2:

- **Narrowing.** The baked scopes when the baked grant is scoped, since the intersection lies inside them. The run-time scopes when the baked grant is whole.
- **Union.** Both sources.

The **read-only system baseline** is the C library and the rest of the OS image, time zones, resolver configuration, CA bundles and character devices:

- macOS: `/usr`, `/System`, `/bin`, `/sbin`, `/dev`, `/private/etc`, `/private/var/db/timezone`, `/private/var/run/resolv.conf`, and the Homebrew OpenSSL `etc` directories.
- Linux: `/usr`, `/lib`, `/lib64`, `/bin`, `/sbin`, `/etc`, `/run/systemd/resolve`, and the `/dev` character devices.

The baseline holds no home directory, no temporary directory and nothing a user writes, so `~/.ssh` and `~/.aws` stay closed. On macOS the working directory itself (`literal`, not beneath it) is readable, because `getcwd(3)` opens `.`, and without it the broker could not resolve a relative path.

### macOS: `sandbox_init(3)`

The plan is rendered as an SBPL profile, the language `sandbox-exec(1)` takes, and applied with `sandbox_init(profile, 0, &err)`. The profile is `(allow default)` followed by a deny-and-allow pair for each restricted access: `file-read-data`, `file-write*`, `process-exec*`, `network-bind` (`local ip`) and `network-outbound` (`remote ip`). Mach services, sysctl and signals are left alone. SBPL's `ip` filter takes only `*` or `localhost` as a host, which is why hosts narrow to ports.

The API is deprecated in `<sandbox.h>`, but it is exported, works, and needs **no entitlement or code signature**. It is declared locally so that the deprecation is not a `-Werror` failure. If `sandbox_init` refuses (for example, inside another sandbox), the program runs under the broker alone, with CAP004.

### Linux: Landlock and seccomp

These calls are guarded by `#if defined(__linux__)`:

1. `prctl(PR_SET_NO_NEW_PRIVS)`.
2. Landlock (`landlock_create_ruleset` / `add_rule` / `restrict_self`, through `syscall(2)`, with the uapi structs copied so an old `<linux/landlock.h>` still builds):
   - The ABI is probed first. Only the restricted accesses are handled: read is `READ_FILE|READ_DIR`; write is the write, make and remove rights, plus `REFER` from ABI 2 and `TRUNCATE` from ABI 3; exec is `EXECUTE`.
   - Each scope becomes a `PATH_BENEATH` rule. A rule on a regular file is masked to the file rights.
   - From ABI 4 (Linux 6.7), `listen` and `connect` ports become `NET_PORT` rules.
3. seccomp, only when `net` is not granted in any form: the socket and `io_uring_setup` filter above. It is written for x86-64 (x32 system calls refused) and AArch64. On any other architecture, CAP004 says the filter is absent.

Landlock and seccomp bind the calling thread and the threads it creates later. That is why they are applied before `main`.

### Degrading: CAP004

CAP004 is a **warning**, given once per cause at start-up. The program runs, and the broker still enforces every grant.

```
CAP004: OS-level enforcement (os_enforce) is partial: <reason>; the in-process broker still enforces every grant
{"diagnostic_id":"CAP004","severity":"warning","stage":"runtime","layer":"sandbox|landlock|seccomp|plan|none","reason":"..."}
```

It has no `fix`, because nothing in the source would correct it. It is emitted when:

- the platform has no OS layer;
- `sandbox_init` refuses the profile;
- the kernel has no Landlock, or it is disabled at boot;
- Landlock has no TCP rules (ABI < 4) while net is scoped;
- an `fs.write` scope does not exist yet, so the rule goes on its nearest existing directory, which the line names;
- a scope cannot be carried as text (a control character in a path), so that access is not OS-restricted;
- the seccomp filter is refused or absent.

The text line escapes control characters, as CAP002's does. The JSON line carries the reason exactly.

### What changes for a program that opts in

- Native code and an ungated sink are refused outside the grants (`EPERM` on macOS, `EACCES` on Linux), instead of succeeding.
- **Children inherit the OS layer.** A granted `git` runs under the same file-system rules: it can read only the read scopes and the baseline. This is the main reason the feature is opt-in.
- Reads the standard library makes on its own outside the baseline (for example, a Linux `/proc` read) are refused. The kernel cannot tell them from the program's own reads.
- The check-then-open race of 138.19 §3.1 is closed for the scope boundary: a component swapped for a symlink that leads out of the scope is refused by the kernel at `open`. The race stays open for the broker's exact-path checks that lie inside a scope.

### Not covered (and why)

- **Hosts and addresses.** Neither SBPL nor Landlock can match a connect by DNS name or CIDR block. The OS layer narrows to ports (and, on macOS, to loopback); the broker narrows to hosts.
- **UDP under a scoped net grant**: Landlock's net rules are TCP only. When net is not granted at all, the seccomp filter covers UDP.
- **`env.write`**: in-process memory.
- **The broker's "the way there" rule** (138.19 round 3): the kernel admits a path anywhere beneath a scope, whatever route the path text took.
- **Other platforms** (the BSDs, Windows): CAP004 only.

## Tests

- **Unit** (`test/stdlib/test_cap_os.c`, run by `make test-stdlib-capabilities`), platform-neutral:
  - the SBPL text: baseline, escapes, the working-directory literal, ports and loopback;
  - the Landlock rights for ABI 1, 2, 3 and 4, handled net with an any-port scope, and the seccomp marker.
  - On the kernel: a forked child applies a plan with no broker in the process and opens files with `fopen`. On a host with no OS layer this half is a named skip.
- **C2230** (`test/conform/C2230_cap_os_enforce.sh`):
  - The extern-C `fopen` bypass works without the opt-in and is refused with it, while the scopes still open.
  - A stdlib copy whose gates all return at once (the "broker removed" test build): `file.read`, `file.write`, `process.spawn`, `net.listen` and `http.geturl` reach the OS without the opt-in, and are refused by the kernel with it, while the granted ones still work.
  - CAP002 is unchanged.
  - The IR differs by exactly one line.
  - `ALLOW_ALL` applies nothing.
  - The CAP004 text and JSON.
  - The manifest parse error, `--show-limits` and `--companion`.
  - `TK_CAP_OS_SHOW`.
  - On Linux, the kernel cases run when Landlock is present (the net cases need ABI 4), and are named skips otherwise.
- **Negative controls:**
  - With the OS layer disabled in a stdlib copy, the ten kernel assertions of C2230 fail.
  - On v3.2.0, every opt-in build fails.

## Open questions

- **A fail-closed mode.** The story said *degrade with a clear diagnostic*, so a missing or partial OS layer is a warning (CAP004). An `os_enforce = "require"` that refuses to start without the full layer would be a new decision.
- **A run-time opt-in** (a launcher turning the layer on for an unmodified binary) was not added. The setting is baked, like the grants.
- **The baseline lists** are a judgement: what a C program needs, minus anything holding user data. They are listed in `src/stdlib/cap_os.h` and documented here, so they can be reviewed.
- **Children inheriting the layer** is the platforms' behaviour, and is documented rather than worked around.
- **The Linux path** is compiled here with `zig cc` for x86_64 and aarch64 glibc and for musl, and syntax-checked with GCC against the Linux headers. Its rule planning is unit-tested on macOS. It has **not been executed on a Linux kernel**: its first run is Linux CI, where C2230 and `test_cap_os` run it, or skip with a named reason when Landlock is absent.
