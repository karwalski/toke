## Context

toke's memory model (`docs/spec/memory-model.md` §6) makes strong **temporal**
safety guarantees — no use-after-free, no double-free, no dangling pointers, no data
races — and the arena design delivers them for pure-toke code. But §6 says nothing
about **spatial** safety (bounds) or **value** safety (overflow/null), and the Epic 120
audit never checked them because 120.4 audited the compiler's *own* C buffers, not the
code the compiler **emits** for user programs. The extended investigation found that a
program written in ordinary, non-FFI toke can still be driven to memory-unsafety:

- **Unchecked array subscript (N1).** The `NODE_INDEX_EXPR` lowering for `arr[i]` /
  `arr.get(i)` emits a raw `getelementptr`+`load` (and, on the store side, a `store`)
  with **no comparison of the index against the length** (`src/llvm.c:3878-3904`) — even
  though the length is stored at `ptr[-1]` and *is* read for `.len()` (`llvm.c:2914`,
  `:3578`). An out-of-range index is a direct **OOB read/write primitive** reachable from
  normal source.
- **The safety is path-dependent, which is worse than uniformly unsafe.** `.set(i;v)`
  *is* bounds-checked (`src/stdlib/str_glue.c:442-467`, silently returning the array
  unchanged on OOB), and `$vec` access is guarded (`src/stdlib/collections.c:275-287`,
  returning 0 / unchanged). So whether `a[i]` is safe depends on which lowering path the
  access happens to take — a trap for readers and for anyone reasoning from §6.
- **Unguarded integer division (N6).** `sdiv`/`srem` are emitted with no divide-by-zero
  and no `INT64_MIN / -1` guard (`src/llvm.c:2756,2768`) — both are LLVM undefined
  behavior, i.e. a crash/UB reachable from `a/b`, `a%b`.
- **Narrow-int overflow is silent.** `i64` `+`,`-`,`*` correctly trap via
  `llvm.{sadd,ssub,smul}.with.overflow` → `tk_overflow_trap` (`llvm.c:2694-2716`,
  `tk_runtime.c:306-311`), but `i8/i16/i32` wrap silently (`llvm.c:2717-2726`).
- **Null-deref.** Struct-field access is a raw GEP on the base (`llvm.c:3618`) with no
  null guard; a `$none`/`0` base (e.g. a map `.get` miss returns 0) dereferenced as a
  struct segfaults. There is no option-type enforcement at codegen.
- **The stack canary the codegen claims to emit is inert.** `llvm.c:7014-7015` sets only
  `"stack-protector-buffer-size"="8"`, which does nothing without an `ssp*` attribute.

The crux — and why this is an owner decision, not an obvious fix — is **performance**.
toke is positioned for efficient, LLM-authored code; a bounds check is a compare+branch
on every indexed access. The question is whether the language's "safe, verifiable code"
promise should include spatial safety by default, paying that cost.

## Decision

Adopt **spatial-safety-by-default in emitted code**, with the same polarity as the
injection ADR (ADR-0011): the safe form is the default the compiler emits; unsafety, if
ever allowed, is explicit and greppable. Sub-decisions are independent.

### (a) Bounds-checked indexing — **Recommend B (checked-by-default + trap), with optimizer elimination now and an explicit opt-out later**

- Emit a bounds check on **both** the load and store paths of `NODE_INDEX_EXPR`
  (`llvm.c:3878-3904`): compare the index (as unsigned) against the length at `ptr[-1]`;
  on failure branch to a new `tk_bounds_trap` that prints `RT003: index out of bounds`
  and `exit(1)`, mirroring the existing `tk_overflow_trap` shape.
- **Converge the silent guards to the same trap.** `.set`/`$vec` today *silently* no-op
  on OOB (`str_glue.c:442-467`, `collections.c:275-287`) — a latent-bug source (a program
  that writes out of range is silently wrong). Make OOB **fail-closed and visible**
  everywhere, so indexing has one semantics regardless of lowering path. (If a saturating
  or option-returning accessor is wanted, provide it as a *named* API — `arr.at(i) ->
  T?` — not as the default `a[i]` behavior.)
- **Cost is mitigated, not ignored.** Story 122.1 turns on `-O2`, under which LLVM
  eliminates provably-in-range checks (loop-invariant / monotone induction indices) — the
  common LLM-generated `for i in 0..len` pattern optimizes to zero residual checks.
  Measure the residual on the Epic 118 corpus.
- **Follow-up opt-out (Option C), not now:** a later, explicit `unchecked { }` block or
  `@nobounds` annotation for measured hot paths — greppable and rare, never the default.
- **Rejected — A (status quo + docs):** documentation does not change what an LLM emits;
  a silent OOB read/write is exactly the failure mode this ADR exists to close.

### (b) Guarded integer division — **Recommend: guard, trap**

Emit a divide-by-zero check and an `INT64_MIN / -1` check before `sdiv`/`srem`
(`llvm.c:2756,2768`); on failure trap `RT004: invalid division`. This is cheap
(predictable branches, only on division) and removes reachable UB.

### (c) Narrow-int overflow — **Recommend: document 2's-complement wrap as defined**

Keep `i64` (the default integer) trapping on overflow, and **specify** that the explicit
sized types `i8/i16/i32` wrap (two's-complement) as *defined* behavior rather than UB
(they already wrap; the fix is to make it a documented guarantee in `memory-model.md` +
`runtime-abi.md`, and to add `@wrapping`/`@checked` opt-in later if demand appears).
Rationale: sized types are an explicit, advanced choice; trapping the default `int`
covers the common case.

### (d) Null / option safety — **Recommend: near-term null-guard trap, option-type enforcement as a follow-up ADR**

Near term, emit a null guard on struct-field deref from a base that codegen cannot prove
non-null (`llvm.c:3618`), trapping `RT005: nil dereference` rather than segfaulting —
notably the map `.get`-miss-returns-0 path. The *correct* long-term fix is compile-time
option/non-null enforcement in the type system (so an unwrapped `$none` cannot reach a
deref); that is a larger type-system change and gets its own ADR.

### (e) Real stack canary for emitted programs — **Recommend: enable**

Replace the inert buffer-size hint (`llvm.c:7014-7015`) with an actual `sspstrong`
function attribute so LLVM inserts canaries in emitted programs, matching what story
122.1 turns on for the compiler itself.

## Trap-code summary

| Code | Condition | Emitted at |
|---|---|---|
| RT002 | i64 add/sub/mul overflow (existing) | `llvm.c:2694-2716` |
| RT003 | array/collection index out of bounds (new, a) | `NODE_INDEX_EXPR`, `.set`/`$vec` |
| RT004 | divide-by-zero / `INT_MIN/-1` (new, b) | `sdiv`/`srem` `llvm.c:2756,2768` |
| RT005 | nil struct-field dereference (new, d) | field GEP `llvm.c:3618` |

## Migration & compatibility impact

- **Transparent for correct programs.** Code that never indexes out of range, divides by
  zero, or derefs nil is unchanged in behavior (and, under `-O2`, largely unchanged in
  performance). Programs with a *latent* OOB/div/nil bug now **trap loudly at the fault
  site** instead of corrupting memory or segfaulting — the desired direction (visible,
  non-exploitable failure).
- **Behavioral change for the silent-`.set` cases:** any code relying on `.set`
  out-of-range silently no-opping now traps; this is rare and almost always a bug. Flag
  with a one-shot scan.
- **Performance is measured, not assumed.** Gate the change on a corpus benchmark (Epic
  118); if a real hot path regresses, that motivates the (c/opt-out) `unchecked` follow-up
  rather than abandoning the default.
- **Spec:** update `memory-model.md` §6 to state spatial-safety + the RT003/004/005 trap
  semantics, so the guarantees match the emitted code.

## Consequences

- "Building on toke = building secure apps" becomes true for the OOB, division, and
  nil-deref classes — not just the UAF/data-race classes — which is the core reason the
  extended investigation was run.
- Resolves findings N1 (121.31) and N6 (121.36) by design; the null-guard closes a class
  the audit only sampled.
- Cost is a bounded, `-O2`-reducible per-index check and new runtime traps; the opt-out
  and the narrow-int carve-out keep the efficiency story intact for advanced users.
- Depends on story 122.1 (`-O2` + mitigations) landing first for the elimination pass.

## Decision needed

Five independent ratifications: **(a)** bounds-checked indexing with a uniform OOB trap;
**(b)** guarded integer division; **(c)** document narrow-int wrap as defined behavior;
**(d)** near-term nil-deref guard (+ commit to a later option-type ADR); **(e)** enable a
real stack canary in emitted code. **Awaiting owner decision before any code is written.**
