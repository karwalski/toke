> **A measurement record, not a published claim.** None of these numbers is in
> `docs/metrics-baseline.md`, and none may be quoted anywhere else until the owner puts
> one there. Each figure below is wall time on one machine. Every one of them comes with
> its metric type, engine, tokenizer, baseline and N.

The 2026-09-18 landscape review (`docs/about/reviews/landscape-2026-09-18.md`) gives two
reasons to adopt grammar-constrained decoding. It is cheap on any grammar (XGrammar's
"near-zero overhead"), and a small grammar should make its mask cheaper still. This
record tests the second point on toke's own artefacts. The engines are open source and
everything ran on the CPU.

## Method

- **Metric 1, mask time.** Wall time of one next-token mask over the whole vocabulary,
  in microseconds. XGrammar's mask call is `GrammarMatcher.fill_next_token_bitmask`, and
  llguidance's is `fill_next_token_bitmask`. Each run is one cold pass on a single
  thread. A fresh matcher consumes each program's real tokens, and the mask is filled
  once at each of 16 evenly spaced token positions, end of text included. A state is
  never filled twice, because llguidance caches the mask of a state it has already seen.
- **Metric 2, compile time.** Wall time to build the matcher state for the vocabulary,
  in seconds: median of 5 runs, one thread, XGrammar's cache off. For llguidance this is
  the grammar build plus its first matcher. llguidance compiles lazily, so this figure
  is a lower bound.
- **Tokenizer.** cl100k_base, through tiktoken 0.14.0: 100,277 ids, and the 16
  unassigned ids are padded with strings that no grammar matches. The table's sha256 is
  `b18b4eea0bbc2915...`, and the full value is in the JSON.
- **Engines.** XGrammar 0.2.9 and llguidance 1.9.1. llguidance ran twice: once with its
  default limits, and once with `step_max_items` raised from 50,000 to 5,000,000.
- **Content.** The same N = 48 programs in three notations. The candidates are the
  git-tracked `.tk` files outside `test/`, 381 of them. A file is kept when `toke.gbnf`
  accepts it, `tkc --dump-ast` serialises it, and `tkc --python-view` renders it as text
  that both CPython's `ast.parse` and the Python-subset grammar accept. That keeps 376,
  and 48 of them, evenly spaced in git order, were measured (paths in the JSON). The 5
  dropped files do not parse under the current toke: 4 linguist samples contain `_` in
  identifiers (E1003), and one committed `results/solutions/` file has an `=` error
  (E2002). `toke.gbnf` agrees with the parser on both.
  - **toke:** the source file. Grammar: `docs/spec/toke.gbnf` (for llguidance,
    `toke.lark` generated from it).
  - **Python (the baseline):** `tkc --python-view` output with its comment header
    removed. Grammar: `bench/mask_cost/python-subset.gbnf`, described below.
  - **JSON (the control):** `tkc --dump-ast` output, compact. Grammar: the standard JSON
    GBNF in `scripts/gbnf_bench.py`. For XGrammar only, its built-in JSON grammar was
    also measured, because that grammar is hand-tuned for the engine.
- **Machine.** Apple M4 Max (arm64, 12 CPUs), macOS 26.7.1, CPython 3.14.7. The run used
  toke commit 677c9c32 with the benchmark files of this branch.
- **Reproduce.** `pip install -r bench/mask_cost/requirements.txt` into a venv, then
  `make bench-mask-cost GRAMMAR_PY=<venv>/bin/python`. Results are written to
  `build/mask-cost/mask-cost-YYYY-MM-DD.json`. The run took about 40 minutes.

### The Python-subset grammar

No CFG engine ships a Python grammar. CPython's grammar is a PEG over a tokenizer that
tracks indentation. `bench/mask_cost/python_subset_gbnf.py` therefore generates a GBNF in
the same style as `toke.gbnf`: character level, with the lexer encoded in the grammar,
identifiers that exclude keywords, and required separators between word tokens. It
allows 4-space indentation to 12 levels, with one copy of the statement rules per level.
It covers everything `--python-view` emits and the common rest of Python 3.12 (its
docstring lists what it leaves out). `make bench-mask-cost-check` checks two properties.
**Coverage:** all 376 `--python-view` outputs that `ast.parse` accepts are accepted.
**Soundness:** across 27 hand-written traps and 3,384 single-edit mutants, the grammar
accepted 1,403 inputs and `ast.parse` rejected none of them.

## Results

Mask time is in µs (median / p90 / max, over N = 768 positions from 48 programs).
Compile time is the median of 5 runs. "Done" counts the programs the engine followed to
the end.

| Grammar (content) | Engine | Compile | Mask median | Mask p90 | Mask max | Done |
|---|---|---|---|---|---|---|
| toke.gbnf (toke) | XGrammar | 1.18 s | 48,270 | 1,044,676 | 4,094,195 | 48/48 |
| python-subset (Python) | XGrammar | 17.2 s | 26,215 | 600,038 | 1,147,214 | 48/48 |
| JSON GBNF (JSON) | XGrammar | 0.012 s | 36,178 | 44,757 | 79,880 | 48/48 |
| XGrammar built-in JSON (JSON) | XGrammar | 0.012 s | 9.2 | 16.5 | 272 | 48/48 |
| toke.lark (toke) | llguidance, step_max_items 5M | 0.004 s | 4,503 | 15,889 | 70,229 | 48/48 |
| python-subset (Python) | llguidance, step_max_items 5M | 0.023 s | 32,586 | 54,297 | 266,411 | 48/48 |
| JSON (JSON) | llguidance, step_max_items 5M | 0.0015 s | 2,544 | 3,331 | 7,094 | 48/48 |
| toke.lark (toke) | llguidance, default limits | 0.005 s | n/a | n/a | n/a | 0/48 |
| python-subset (Python) | llguidance, default limits | 0.024 s | n/a | n/a | n/a | 0/48 |
| JSON (JSON) | llguidance, default limits | 0.0011 s | 2,589 | 4,108 | 10,752 | 48/48 |

With default limits, llguidance stopped every toke and Python program with "Too many
items (limit 50000; mask); try avoiding single-byte/short lexemes". Its timings for those
two rows cover only the positions before the stop, so they are not reported.

## What this says

1. **The engine and the way a grammar is written decide the cost, not the size of the
   language.** Take the same JSON content, the same engine and the same vocabulary. The
   textbook JSON GBNF costs 36,178 µs per mask at the median, and XGrammar's tuned
   built-in grammar costs 9.2 µs (N = 768 positions, cl100k_base). The "near-zero
   overhead" result belongs to grammars written for the engine. These character-level
   artefacts get none of it.
2. **Under XGrammar, toke.gbnf is the most expensive of the three grammars per mask.** Its
   median is 48,270 µs, against 26,215 µs for the Python subset, with the same tokenizer
   and N = 768 positions from 48 programs each. Its tail is heavier too: 1.04 s at p90
   against 0.60 s. It compiles about 15 times faster (1.18 s against 17.2 s), because the
   Python subset repeats its statement rules for each indentation level.
3. **Under llguidance with raised limits, toke is about 7 times cheaper per mask than the
   Python subset.** The medians are 4,503 µs against 32,586 µs (same tokenizer, N = 768),
   and toke stays below the Python subset at p90 and at max. This is the only setup in
   which toke's grammar is the cheaper one.
4. **Neither character-level grammar is usable as shipped.** XGrammar's medians are tens
   of milliseconds per token. llguidance will not run either grammar under its default
   limits. JSON runs under those limits because its grammar has longer lexemes.

The claim that "a small grammar makes the mask cheap" is therefore **not supported** by
toke's current artefacts. The cost these grammars pay comes from their character-level
form, which encodes the lexer as grammar rules so that a context-free engine sees toke's
lexical rules. It does not come from the size of the language. Two pieces of work would
test the claim fairly:

- an engine-tuned toke grammar: multi-character lexemes for llguidance, and lookahead
  assertions with inlined whitespace for XGrammar;
- the same treatment for the Python baseline.

Both are filed as follow-ups (131.141).

## Numbers for the owner (not added to metrics-baseline.md)

Each figure lists its metric type, engine, tokenizer, baseline and N.

- Mask time median: toke 48,270 µs against the Python subset at 26,215 µs (XGrammar
  0.2.9, cl100k_base, N = 768 positions from 48 programs, CPU, one thread).
- Mask time median: toke 4,503 µs against the Python subset at 32,586 µs (llguidance
  1.9.1 with `step_max_items` 5,000,000, cl100k_base, N = 768 from 48 programs).
- Compile time median: toke 1.18 s against the Python subset at 17.2 s (XGrammar 0.2.9,
  cl100k_base, 5 runs, one thread).
- Control: JSON GBNF at 36,178 µs against XGrammar's built-in JSON at 9.2 µs (XGrammar
  0.2.9, cl100k_base, N = 768).
- Default limits: llguidance 1.9.1 stops 48 of 48 toke programs and 48 of 48 Python-subset
  programs, and finishes 48 of 48 JSON programs.

The full record is the JSON `build/mask-cost/mask-cost-2026-11-23.json`. It is not
committed, because `build/` is ignored. It also holds p99, mean, allowed-token counts per
mask and the selected paths.
